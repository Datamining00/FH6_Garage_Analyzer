# 자동 리버리 감지 분리 — 2026-09-11

기준 브랜치: `v1.4-rc1-wheel-morph-w3`, 작업 시작 커밋: `1ebff60`.

## 구현

- 3초 타이머는 별도 단일 작업에서 폴더 이름·식별 번호와 header/C_livery의 크기, 수정·생성 시각, 파일 식별 번호를 확인한다. 총개수가 같아도 구성 변화가 감지된다.
- 안정된 두 관측 사이에 최소 2초를 요구한다. 3초 타이머 특성상 보통 다음 확인 주기에 상세 분석한다. 최초 비교 기준의 검증 이후에는 변화가 있을 때만 분석하며, 이미 검증한 파일은 메모리 캐시를 재사용한다.
- header 파싱, C_livery 압축 블록의 길이·압축 해제 검증, 분석 전후 메타데이터 일치를 요구한다. 필요한 파일의 부재, 0바이트, 파싱 오류, 접근 오류는 전체 관측을 보류한다. 빈 저장 목록으로 대체하지 않는다.
- 기존 snapshot 비교와 추가·삭제·중복 분류를 사용한다. 마지막 메인 목록과 현재 저장의 차이이므로 중복 누적이 없고, 추가 후 삭제된 항목은 차이에서 빠진다. GUID/내용으로 유일하게 대응되는 단순 위치 이동은 삭제로 표시하지 않는다.
- 자동 결과는 변동 카운터와 열린 변동 창의 카드만 갱신한다. 메인 result, 카드 객체·배열, 검색·필터, 스크롤, 카드 선택은 유지한다. 자동 변동 카드는 기존 보관 카드 모양으로 표시하며, 자동으로 동작을 실행하지 않는다.
- 수동 스캔은 진행 중인 자동 관측을 취소하고 종료 후 시작한다. 성공 시 기존 Qt GUI 완료 슬롯에서 새 기준으로 전환하고 변동을 초기화한다. 경로 변경/OFF/새 스캔 세대에 속하지 않는 결과는 폐기한다.
- 모달·백업·내보내기·들여오기·스캔·이동 작업 중에는 자동 결과를 보류한다. 카드 선택 중에는 새 관측을 시작하지 않는다. 작업을 큐에 누적하지 않는다.
- 삭제 목적의 방향키 이동 성공을 삭제 완료로 취급하지 않는다. 확인된 현재 리버리로 이동 위치 계산만 갱신한다. 메인 카드를 제거하지 않으며, 재이동 전과 지연 실행 시 잠금을 재검사한다. 적용 중 리버리 경고 옵션은 기존 경로를 사용한다.
- 게임 파일은 읽기만 한다. 썸네일이 있으면 기존 이미지의 로컬 이력 복사만 이용하며 이미지 생성이나 2D/3D 렌더링을 실행하지 않는다.

## 검증

- Python 3.12.14 / PySide6 6.11.2: 전체 1,027개 테스트 통과. 독립 빌드 환경에서도 동일한 1,027개 통과.
- 임시 저장소: 동수 교체, 추가 후 삭제, 부분 다운로드·삭제, 파일 교체의 일시적 공백, 접근 오류, 분석 중 변경, 반복 관측, 변경 파일만 재분석, 위치 이동, 중복 분류 검증.
- 컨트롤러: 단일 작업, OFF 시 미시작, OFF/경로 변경/수동 결과 전환 후 늦은 결과 폐기, 작업 충돌 시 재시도 검증.
- 실제 앱 클래스와 전체 패치 스택을 사용하는 별도 UI 검사: 메인 카드 배열·스크롤·선택 유지, 변동 카운트/카드 일치, 열린 변동 창 갱신, 두 차례 삭제 목적 재이동, 잠금 후 차단 검증. 방향키 전송 함수만 모의 처리하여 실제 게임 입력은 보내지 않았다.
- 실제 QThread 자동 관측과 수동 스캔을 겹쳐 취소·대기·스캔 성공·기준 초기화까지 검증했다. 이 검사를 통해 완료 처리 연결 위치를 기존 Qt 슬롯으로 바로잡았다.
- 2,937개 임시 리버리(필수 파일 5,874개), 12회 메타데이터 확인: 중앙값 134.8ms, 최대 141.3ms, 프로세스 CPU 시간 중앙값 140.6ms. 3초 주기로 환산하면 한 코어 기준 약 4.7%의 CPU 시간이다. 다른 PC나 저장장치의 보장값은 아니다.
- 평상시 확인에서 리버리 파일 본문 읽기 0바이트를 코드와 읽기 차단 테스트로 검증했다. 파일시스템 메타데이터 I/O는 발생하며 물리 디스크 전송량을 따로 측정한 수치는 아니다.
- 일반판·포터블 최종 빌드 성공. 자동 인식/백업을 끈 임시 설정에서 각 실행 파일의 실제 시작·정상 종료(exit code 0) 확인. 각각 약 3.24초, 2.27초(시작 후 1.5초 종료 타이머 포함).
- 최초 일반 테스트 실행의 3건 실패는 긴 Windows 경로와 QSettings 저장 환경 문제였다. 짧은 임시 AppData와 INI 설정을 사용하는 재현 가능한 격리 실행기로 모두 통과했다.
- 패키징 중 개발용 Poppler의 동명 ICU DLL 혼입을 발견했다. build_exe.ps1에서 PyInstaller의 PATH를 Windows 시스템 경로와 빌드 환경으로 제한해 해결하고 최종 실행을 검증했다.

## 확인 범위와 한계

- 실제 게임 저장 데이터를 변경하는 테스트는 하지 않았다. 사용자 PC에서 실제 다운로드·삭제·재이동을 수행하는 실행 확인은 아직 미완료다.
- 이번 변경은 Python 3.12에서 재검증했다. 이전 배포의 Python 3.13 검증 결과를 이번 변경의 검증으로 간주하지 않는다.
- 두 확인 사이에 생성·완전 삭제되어 흔적이 없는 항목은 포착할 수 없다. 디스크 관측만으로 게임의 저장 트랜잭션 완료를 절대적으로 증명할 수는 없다. 불완전 파일은 보류하지만, 유효하고 안정적인 전체 상태가 관측된 뒤 다시 바뀌면 다음 확인에서 재평가한다.
- 불확실한 항목이 하나라도 있으면 해당 주기의 전체 차이 반영을 보류하는 보수적 정책이다. 영구적으로 손상된 필수 파일이 있으면 자동 카운터 갱신도 보류되며 수동 새로고침은 사용할 수 있다.
- 3D 정확도·부품 숨김·이름 기반 부품 분류·휠 hidden·관련 옵션 설명은 변경하지 않았다. sources/ 및 작업 전부터 있던 비추적 자료도 수정하지 않았다.
