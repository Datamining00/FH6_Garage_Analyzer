# FH6 Assistant

**FH6의 리버리·튜닝·차량 정보를 한곳에서 확인하고 관리하는 Windows용 데스크톱 프로그램입니다.**

로컬 저장 데이터와 썸네일 캐시를 분석하여 콘텐츠를 검색·정렬·분류하고, 리버리를 백업하거나 게임 내 위치로 이동하는 작업을 보조합니다. 리버리의 2D·3D 미리보기와 적용 상태 확인도 지원합니다.

이 문서는 **v1.5 기능 기준**입니다. 실제 공개된 파일과 변경 사항은 [Releases](https://github.com/Datamining00/FH6_Garage_Analyzer/releases)에서 확인해 주세요.

> [!IMPORTANT]
> FH6 Assistant는 비공식 커뮤니티 도구이며 Microsoft, Xbox, Turn 10 Studios, Playground Games 또는 Forza와 제휴하거나 보증받은 제품이 아닙니다.
>
> 분석·검색·표시와 달리 **백업 복원·잘라내기·썸네일 쓰기는 파일을 변경할 수 있습니다.** 해당 기능을 사용하기 전에 대상과 백업 상태를 확인해 주세요. 게임 업데이트와 저장 상태에 따라 분석 결과나 이동 위치가 달라질 수 있습니다.

## 시작하기

1. 일반판 실행 파일 또는 포터블 ZIP을 내려받습니다.
2. 포터블은 **압축을 모두 푼 뒤** 폴더 안의 실행 파일을 실행합니다. 내부 파일은 함께 유지해 주세요.
3. `세이브 폴더 선택`에서 FH6의 실제 로컬 저장 폴더를 지정합니다.
4. `캐시 경로 선택`에서 사용 중인 `CacheThumbnails` 폴더를 지정합니다.
5. `전체 새로고침`으로 목록을 구성합니다.

| 파일 | 용도 |
|---|---|
| `FH6 Assistant v1.5.exe` | 일반판 단일 실행 파일 |
| `FH6-Assistant-v1.5-Portable.zip` | 실행 파일과 구성 파일을 함께 제공하는 포터블 패키지 |
| `FH6-Assistant-v1.5-Full-Source.zip` | 앱 소스·빌드 자료·외부 라이브러리 대응 소스 |

일반판과 포터블 실행에는 Python이나 PySide6를 별도로 설치하지 않아도 됩니다. **일부 미리보기 도구와 데이터는 첫 사용 시 내려받으므로 인터넷 연결이 필요할 수 있습니다.**

포터블은 `C:\FH6`처럼 짧은 경로에 풀어 주세요. 사용자 설정은 실행 파일 옆이 아닌 `%LOCALAPPDATA%\FH6GarageAnalyzer`에 저장되므로, 포터블 폴더만 옮겨도 설정까지 함께 이동하는 방식은 아닙니다.

| 백업·복원 | 선택 리버리 백업, 자동 백업, 외부 자료 가져오기 및 복원 |

| 진단·성능 확인 | 문제 확인용 진단 내보내기와 성능 측정 화면 |

## 리버리 목록과 분류

리버리 카드에서 차량명, 제목, 제작자, 설명, 다운로드 날짜 등 확인 가능한 정보를 표시합니다. 썸네일 확대, 상세 정보, 폴더 열기, 메모와 분류 버튼을 사용할 수 있습니다. 차량명·리버리명·제작자명은 클릭하여 복사할 수 있습니다.

### 내 디자인 리버리와 경매장 리버리

- **내 디자인 리버리:** 일반 `Livery` 데이터를 대상으로 합니다.
- **경매장 리버리:** 앱에서 `SoulBoundLivery` 데이터를 구분해 보여 주는 명칭입니다. 이 명칭만으로 차량의 실제 획득 경로가 경매장이라고 단정하지 않습니다.

두 목록은 전환하여 확인합니다. `SoulBoundLivery`의 제목·제작자 정보를 확정하지 못하면 기본값이나 미확인 상태가 표시될 수 있습니다.

캐시 썸네일은 `.manifest`의 식별·등록 정보와 대응되는 파일을 확인해 연결합니다. 이미지 파일이 존재해도 연결 정보가 불충분하면 썸네일을 표시하지 못할 수 있습니다.

### 검색·정렬·필터

- 차량명, 차량 식별 번호, 리버리명, 제작자, 설명, 메모 검색
- 기본 순서, 브랜드명, 제작자명, 다운로드 날짜 정렬
- 동일 차량 또는 동일 제작자끼리 묶어 표시
- 원·삼각형·X·분류 없음, 메모 있음·없음 필터
- 중복, 숨김, 잠금, 백업되지 않은 리버리 등 상태 필터
- 확인된 정보를 기준으로 적용·미적용 리버리 구분

중복 판정은 이름만 비교하지 않고 `C_livery` 파일의 실제 내용을 기준으로 합니다. 앱의 정렬·그룹화는 **게임 안의 리버리 배열을 변경하지 않습니다.**

### 메모·숨김·잠금

메모와 원·삼각형·X 분류, 숨김·잠금 상태는 앱의 로컬 사용자 정보로 관리합니다.

숨긴 항목은 일반 목록에서 제외되며 `필터 → 숨김`에서 다시 확인하고 해제할 수 있습니다. 숨김 자체는 게임의 리버리를 삭제하지 않습니다. 현재 이동 보조는 숨김 항목을 이동 대상과 계산 목록에서 제외하므로 게임 화면의 목록 조건도 확인해 주세요.

잠금은 앱에서 지원하는 삭제 목적 이동·잘라내기 등으로부터 항목을 보호하기 위한 기능입니다. **게임 자체에서의 삭제를 차단하는 기능은 아닙니다.** 백업 항목의 보호 상태와 원본 리버리의 잠금은 구분됩니다.

## 자동 리버리 감지와 최근 변경사항

`설정 → 자동 리버리 인식`을 켜면 저장 데이터의 변화를 감지하여 추가·제거·중복 카운트와 최근 변경사항을 갱신합니다.

**자동 감지만으로 메인 카드 목록을 다시 구성하지 않습니다.** 사용 중인 검색·필터·스크롤·선택을 유지하며, 메인 목록 반영은 `전체 새로고침`으로 수행합니다.

최근 변경사항 창도 일반 목록과 같은 카드 구성으로 표시합니다. 삭제되어 원본이 없는 항목은 실행할 수 없는 기능을 비활성화합니다.

저장 중인 파일, 부분 삭제, 파일 교체, 접근 오류는 확정된 변화로 처리하지 않도록 검사합니다. 경로 변경·수동 새로고침·자동 인식 해제 후에는 이전 분석 결과를 폐기합니다.

## 백업·복원·내보내기

선택한 리버리를 별도 백업 저장소에 보관하고 백업 탭에서 확인할 수 있습니다.

- 수동 백업과 선택적 자동 백업
- 외부 폴더에서 자료 가져오기
- 백업 목록의 검색·미리보기·관리
- 지원되는 항목의 복원과 복사·잘라내기 동작
- 잠금에 따른 삭제·잘라내기 보호
- 중복 백업 허용 조건 설정

설정에서 다음 조건을 각각 선택할 수 있습니다.

- `이름이 다른 리버리 중복 백업 허용`
- `이름이 같은 리버리 중복 백업 허용`

> [!NOTE]
> **현재 리버리 백업은 메모·원·삼각형·X·숨김·원본 잠금의 백업 시점 스냅샷을 포함하지 않습니다.** 사용자 기록까지 보존하려면 아래에 설명한 앱 사용자 데이터도 별도로 백업해 주세요. 백업 사용자 기록의 수동 동기화 기능은 현재 버전에 포함되지 않습니다.

## 썸네일 표시와 실제 파일에 쓰기

앱 카드의 표시 설정과 **실제 썸네일 파일에 표시를 그리는 기능**은 별개입니다.

- 다운로드 날짜는 카드 썸네일의 상단에 표시합니다.
- `Auction`과 잠금 표시는 카드 썸네일의 하단에 배치합니다.
- `썸네일에 쓰기`를 켜면 해당 표시를 실제 썸네일에도 반영합니다. 날짜는 파일에 그리지 않습니다.

### 대상과 원본 보관

일반 리버리는 해당 폴더 썸네일을 처리하고, 정확히 연결되는 현재 등록 캐시가 있으면 함께 처리합니다. `SoulBoundLivery`도 식별 가능한 캐시 썸네일을 사용합니다.

연결이 모호하거나 다른 항목과 공유되는 등 안전하게 확정할 수 없는 캐시는 쓰기를 건너뛰고 결과를 표시합니다. 미적용 경매장 리버리는 새 표시 대상에서 제외하며, 표시·복원할 내용이 없는 일반 리버리는 불필요한 썸네일 탐색을 생략합니다.

쓰기 전에 원본을 별도로 보관하며 **파일명·확장자·이미지 형식을 유지**합니다.

- 경매장 표시를 해제하면 `Auction` 표시를 제거합니다.
- 잠금을 해제하면 잠금 표시를 제거합니다.
- `썸네일에 쓰기`를 끄면 앱이 넣은 표시를 원복합니다.
- 게임이 파일을 교체한 경우에는 오래된 원본으로 무조건 덮어쓰지 않습니다. 파일 상태에 따라 원복을 보류할 수 있습니다.

### 재적용

게임이 썸네일을 교체하거나 표시가 사라진 경우 설정의 `재적용`을 사용할 수 있습니다. 검증한 현재 이미지에 표시를 다시 반영하며, 새 원본 보관과 쓰기가 성공한 뒤 더 이상 사용하지 않는 이전 원본 백업을 정리합니다.

썸네일 관련 설정을 바꾸지 않고 저장하는 경우에는 같은 쓰기 작업을 불필요하게 다시 실행하지 않도록 처리합니다.

## 2D·3D 미리보기

- 리버리의 면별 2D 이미지 확인
- 차량 모델에 리버리를 반영한 3D 미리보기
- 확대·축소와 화면 맞춤
- 돋보기로 여는 미리보기 창의 모니터 중앙 배치
- 렌더링 캐시 저장·재사용 선택
- 3D 차량 재질 생략 선택
- 렌더링 동시 작업 수 자동·수동 설정

2D는 기본 화면 확대율 100%로 열립니다. 3D는 공통 썸네일형 기본 시점을 100% 기준으로 사용합니다. **이는 렌더링 해상도 배율을 1배로 낮춘다는 의미가 아닙니다.**

게임 차량 자산을 읽을 수 있어야 하며, 첫 사용 시 외부 변환기·렌더러·데이터 다운로드가 필요할 수 있습니다. 차량별 게임 썸네일과 시점이 완전히 같거나 모든 재질·부품이 게임과 동일하게 표현되는 것은 아닙니다.

## 수동 메모리 스캔과 적용 상태

`메모리 스캔`은 실행 중인 FH6 프로세스의 메모리를 **읽기 전용**으로 확인합니다. 결과를 이용해 적용 상태와 관련 필터·집계를 갱신합니다.

스캔 결과를 정상 반영한 뒤에는 필요한 목록 새로고침을 수행합니다. 상태를 확정하지 못하거나 스캔이 실패하면 기존 정상 결과를 유지하며, 미확인 상태를 미적용으로 단정하지 않습니다.

**자동 메모리 스캔이나 주기 실행 옵션은 없습니다.** 게임 상태가 바뀌었으면 사용자가 다시 스캔해야 합니다. 저장 파일의 자동 감지와 메모리 스캔은 서로 다른 기능입니다.

## 게임 내 리버리 위치 이동 보조

게임에서 다음 화면을 연 뒤 사용합니다.

```text
집 → 자동차 → 디자인 및 도색 → 내 디자인
```

리버리 카드의 이동 버튼을 누르면 목록의 첫 항목을 기준으로 위치를 계산하고 FH6 창에 필요한 키 입력을 전송합니다. 시작 대기 시간과 입력 간격을 조정할 수 있습니다.

`삭제하기 위해 이동`과 `적용하기 위해 이동`은 **해당 위치로 이동하는 보조 기능**입니다. 이동했다는 이유만으로 삭제나 적용이 끝났다고 처리하지 않습니다. 기존 잠금과 적용 중 경고도 유지합니다.

### 삭제 목적 이동 후 감시

1. 이동한 대상의 폴더와 필수 파일을 약 250ms 간격으로 확인합니다.
2. 삭제가 연속 확인되면 **이동 계산 목록에서만** 제외합니다. 메인 카드는 자동으로 새로고침하지 않습니다.
3. 다음 대상으로 이동하기 전에 이전 대상이 남아 있는지 재확인합니다. 상태가 불확실하면 이동을 보류합니다.
4. 30초가 지나면 주기 감시를 종료하되, 다음 이동 때 재확인할 대상을 기록합니다.

전체 새로고침·저장 경로 변경·프로그램 종료 시에도 감시를 종료합니다.

신규 다운로드가 감지됐지만 아직 메인 목록에 반영하지 않은 경우, 두 이동 기능 모두 **실제 새로고침 완료 → 위치 재계산 → 이동** 순서로 처리합니다. 새로고침이 실패하면 이동하지 않습니다.

게임의 목록 조건이나 입력 환경이 달라지면 이동 결과도 달라질 수 있으므로 실제 선택 위치를 확인해 주세요.

## 튜닝·차량·제작자 정보

저장된 튜닝은 차량, 제작자, 부품 식별 번호 및 파일에 기록된 설정값을 읽어 표시합니다. 튜닝 파일 자체를 편집하는 기능은 제공하지 않습니다.

차량 데이터베이스는 차량 식별 번호를 차량명과 연결합니다. 등록되지 않은 차량에는 사용자 차량명을 지정할 수 있고, 데이터베이스 업데이트 확인과 원본 출처 열기를 지원합니다. 업데이트가 완료되면 목록을 새로고침합니다.

제작자 이름 관리 화면에서는 저장된 제작자 정보를 확인하고 앱에서 사용하는 이름 정보를 관리할 수 있습니다.

## 저장 폴더와 썸네일 캐시 경로

실제 경로는 설치 환경과 플랫폼에 따라 다를 수 있습니다. 아래는 경로의 예이며, 반드시 본인 환경의 실제 폴더를 지정해 주세요.

**Xbox App / Microsoft Store 저장 폴더 예:**

```text
C:\XboxGames\GameSave\pgs\u_XXXXXXXXXXXX_XXXXXX
```

환경에 따라 `current`, 숫자로 된 버전 폴더 또는 `ContainersRoot`를 선택할 수도 있습니다.

**Xbox App / Microsoft Store 썸네일 캐시 예:**

```text
%LOCALAPPDATA%\Packages\<FH6 Package>\LocalCache\Local\LocalStorage_Cache\CacheThumbnails
```

**Steam 썸네일 캐시 예:**

```text
%LOCALAPPDATA%\ForzaHorizon6\LocalStorage_Cache\CacheThumbnails
```

### 썸네일이 보이지 않을 때

1. 지정한 폴더가 실제 게임에서 사용하는 `CacheThumbnails`인지 확인합니다.
2. 폴더에 `.manifest`가 있는지 확인합니다.
3. 게임에서 해당 차량·리버리의 썸네일이 표시되도록 확인한 뒤 `전체 새로고침`을 실행합니다.

캐시 파일이 있어도 식별 정보가 부족하면 `No thumbnail`이 표시될 수 있습니다. **캐시 폴더 초기화는 필수 설치 절차가 아닙니다.** 캐시를 수동 관리할 필요가 있다면 게임과 앱을 종료하고 원본을 별도 보관한 뒤 작업해 주세요.

## 사용자 데이터와 백업

앱 사용자 데이터의 기본 위치:

```text
%LOCALAPPDATA%\FH6GarageAnalyzer
```

| 파일·폴더 | 내용 |
|---|---|
| `annotations.json` | 메모 및 원·삼각형·X 분류 |
| `ui_preferences.json` | 화면 설정과 숨김·보호 상태 등 사용자 관리 정보 |
| `app_options.json` | 자동 처리·표시·미리보기 등 프로그램 설정 |
| `thumbnail_originals` | 썸네일 쓰기 전 원본과 복원 관리 정보 |
| `preview3d_runtime` | 미리보기 외부 도구·의존성과 생성 데이터 |

위 표는 주요 항목입니다. 사용자 데이터를 옮기거나 백업하려면 앱을 종료한 뒤 필요한 파일을 함께 보관해 주세요. 특히 썸네일 표시를 원복할 예정이라면 `thumbnail_originals`를 임의로 삭제하지 마세요. `preview3d_runtime`에는 실행 도구와 의존성도 있으므로 폴더 전체를 단순 렌더링 캐시로 취급하면 안 됩니다.

- 저장 폴더·캐시의 읽기 권한

Windows 10/11의 모든 빌드, 그래픽 드라이버, 설치 플랫폼과 새 PC 조합을 검증한 것은 아닙니다. 3D 창의 최소 너비보다 좁은 화면에서는 일부가 화면 밖으로 나갈 수 있습니다.

v1.5 라이선스 보완판은 Python 3.12.14 환경에서 **자동 테스트 1,097개**, 임시 데이터 기반 UI 검사, 일반판·포터블·소스 실행, 소스 ZIP에서의 재빌드를 확인했습니다. **이 결과는 실제 게임 조작이나 모든 사용자 환경의 정상 동작을 보증하지 않습니다.** 실제 게임 저장 데이터와 사용자 썸네일을 변경하는 검증은 수행하지 않았습니다.
