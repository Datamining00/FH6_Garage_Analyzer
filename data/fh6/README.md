# FH6 vehicle-data mirror and snapshots

This directory is generated by the `Sync FH6 Vehicle Data Gist` GitHub Actions workflow.

Source Gist:

- `https://gist.github.com/Datamining00/30fe44689fad7ba5e99e2381927b7730`
- Source file: `FH6_Vehicle_Data.json`

The workflow is read-only toward the Gist. It never updates or overwrites the Gist.

## Layout

- `mirror/FH6_Vehicle_Data.json`
  - Exact mirror of the current Gist file.
- `normalized/latest.json`
  - Latest normalized dataset keyed by vehicle ID.
  - Every original vehicle field is retained and the top-level vehicle name is stored as `name`.
- `normalized/previous.json`
  - Previous normalized state.
- `snapshots/by-hash/<sha256>.json`
  - Full normalized snapshots, content-addressed by the normalized vehicle-data hash.
  - Identical data reuses the same snapshot file to avoid repository bloat.
- `runs/YYYY/MM/DD/HHMMSSZ.json`
  - One small manifest for every workflow execution.
  - Points to the full snapshot and the corresponding field diff.
- `diffs/latest.json`
  - Latest ID-based field diff.
- `diffs/history/YYYY/MM/DD/HHMMSSZ.json`
  - Per-run field diff history.
- `state.json`
  - Current sync state and references to the most recent run, diff, and snapshot.

## Comparison rules

Vehicle `id` is the comparison key.

For a matching ID, the comparison covers the full normalized record, including the canonical vehicle name and every field present in the mirrored Gist. This detects:

- added IDs,
- removed IDs,
- renamed vehicles,
- individual field modifications,
- fields added or removed from a record.

Missing fields and explicit JSON `null` values are distinguished in the diff output.
