# FH6 Assistant v1.3.2 work notes

- Base: `v1.3.1-work`
- Adds `SoulBoundLivery` / auction-livery visibility without adding those records to the in-game My Designs navigation session.
- Adds independent `My Designs liveries` and `Auction liveries` display toggles; both may be enabled at the same time.
- Auction-livery cards have no in-game move control. A second guard also prevents programmatic navigation requests for `SoulBoundLivery` records.
- Auction liveries do not participate in the existing duplicate-My-Designs logic.
- Adds a selectable/auto-detected `CacheThumbnails` path. Known Microsoft Store/Xbox and Steam-style LocalAppData candidates are accepted only when a real `.manifest` is present.
- Parses only the verified first table of `.manifest` (v2) to resolve GUID-named WebP files.
- Uses the immutable timestamp encoded in the SoulBound container name only for the user-facing download sort value; filesystem CreationTime/ModifiedTime are not used for thumbnail identity.
- Thumbnail matching is deterministic: the final 16 raw bytes of the livery header are encoded with RFC-style 5-bit grouping using the Crockford alphabet `0123456789abcdefghjkmnpqrstvwxyz`. The resulting 26-character token is matched to the `u<token>` portion of the manifest logical filename together with the CarOrdinal.
- If the same CarOrdinal + 26-character token has multiple manifest rows, v1.3.2 treats the thumbnail as ambiguous instead of selecting one arbitrarily.
- If the mapped GUID WebP is missing/evicted, the auction livery remains visible with no thumbnail.
- `.manifest` is a thumbnail-combination cache/history, not a reliable current-applied-livery state table. Current applied/misapplied status is therefore not shown in v1.3.2.

Verified examples include duplicate CarOrdinal 0625 SoulBound records and the CarOrdinal 0368 auction livery. The direct header-token mapping is covered by regression tests and does not depend on cache file timestamps or manifest insertion order.
